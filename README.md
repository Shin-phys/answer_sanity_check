# 答えの吟味タイムアタック

導いた式が正しいかを、**解き直さずに**「単位・極限・増減」の3つの観点で見抜く練習をする、高校物理のWebアプリです。
インストール・ログイン不要で、スマートフォン・Chromebook・PCのブラウザで動きます。

- 公開URL: https://shin-phys.github.io/answer_sanity_check/
- 仕様書: [docs/spec/README.md](docs/spec/README.md)

## ねらい

| 観点 | 問い | 例 |
| --- | --- | --- |
| 単位 | 求めたい量と単位が合うか | 落下時間が √(2gh) なら単位は m/s。時間にならない |
| 極限・特別な場合 | 極端な条件で当然の結果になるか | 斜面の加速度が g cosθ なら、θ=0（水平）でも g で加速してしまう |
| 増減 | 条件を変えたときの増え方・減り方が自然か | 摩擦が大きいほど加速度が増える式はおかしい |

誤った式が画面に出るのは、レベル1（「ある人が出した答え」と明示）とレベル4（4つの候補から選ぶ）、レベル5（答案のまちがい探し）だけです。
レベル2・3では**正しい式だけ**を表示し、その式の極限・増減についての説明が正しいかを判定します。

## レベル

| レベル | 名前 | 形式 |
| --- | --- | --- |
| 1 | 単位チェック | タイムアタック。ある人が出した答え（誤りを含むことがある）の単位が、合う／合わない の2択 |
| 2 | 極限チェック | タイムアタック。正しい式と、極限についての説明（例: 「m を 0 に近づけると、加速度は g/2 に近づく」）を見て、その通り／誤っている の2択 |
| 3 | 増減チェック | タイムアタック。正しい式と、増減についての説明（例: 「おもりが重いほど、周期は長い」）を見て、その通り／誤っている の2択 |
| 4 | 計算せずに選べ | じっくり。4つの式から正しい式を1つ選ぶ。検算ボタンで各式の結果を見られる |
| 5 | まちがい探し | じっくり。答案の中から誤りのある行と、誤りの種類を選ぶ |

タイムアタックの規則は、12問正解でゴール、誤答時は1.5秒操作不能（その間に理由を表示）、ボタンの位置は固定です。
結果画面には、タイム・正答率・自己ベストとの差・直近20回の推移・まちがえた問題の解説が出ます。
PCでは ← → キーでも答えられます。

## 授業での使い方

- 授業冒頭の1〜3分に、レベル1〜3を帯活動として継続する。
- 演習や家庭学習では、時間制限のないレベル4・5を使う。
- 下のURLパラメータをつけたリンクやQRコードを配ると、目的のレベルに直接入れます。

## URLパラメータ

| パラメータ | 意味 | 例 |
| --- | --- | --- |
| `lv` | レベル（1〜5）を指定してすぐ始める | `?lv=1` |
| `unit` | 出題する単元。`basic`（物理基礎・力学）、`mech`（物理・力学）、`other`（熱・波・電気）をカンマ区切り。省略時は `basic` | `?lv=2&unit=basic,mech` |
| `card` | `0` でレベル1の単位カード（文字ごとの単位の表示）を消す | `?lv=1&card=0` |
| `big` | `1` で投影モード（文字を大きく） | `?lv=4&big=1` |

## 記録について

記録（日時・レベル・タイム・正答数・まちがえた問題）は、端末のブラウザ内（localStorage）にだけ保存します。
氏名などの個人情報は扱わず、外部への送信やアクセス解析もありません。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm test         # 自動テスト
npm run build    # 本番ビルド（dist/）
```

main ブランチへのプッシュで、GitHub Actions がテスト・ビルドを行い GitHub Pages に公開します。
初回のみ、リポジトリの Settings → Pages → Build and deployment → Source を「GitHub Actions」にしてください。

### 構成

| 場所 | 内容 |
| --- | --- |
| `src/core/expr.ts` | 式の構文解析・数値評価・TeX変換 |
| `src/core/dim.ts` | 単位（次元）の計算と途中式の生成 |
| `src/core/checks.ts` | 極限・増減の数値判定 |
| `src/core/bank.ts` | 各式の合否の計算、出題、説明文の生成 |
| `src/data/situations.ts` | 収録問題（20状況・81式、極限29・増減35の検算） |
| `src/core/physics.test.ts` | 正しい式が基本法則を満たすことの確認 |
| `src/data/mistakes.ts` | レベル5の問題（4問） |
| `src/data/symbols.ts` | 文字の表示・単位・次元 |
| `src/ui/` | 画面 |

### 問題を追加するには

1. `src/data/situations.ts` に状況を1つ追加する（正しい式、誤答候補、検算）。新しい文字は `src/data/symbols.ts` に定義する。
   - 極限の検算には、正しい式がとる値 `expect` と、レベル2で「誤っている説明」に使う値 `alts` を書く。
   - 増減の検算には、正しい式での動き `expect`（up／down／flat）と、説明の文 `lead`・`words` を書く。
2. 説明の正誤は書かない。正しい式の数値計算から式エンジンが決める。極限で不合格になる誤答候補には、そのときの値を `gives` に書く（レベル4の解説に使う）。
3. `src/core/physics.test.ts` に、追加した正しい式が基本法則（運動方程式、保存則など）を満たすことの確認を1行足す。
4. `npm test` を実行する。次のどれかに当たるとテストが失敗する。
   - 正しい式が基本法則を満たさない
   - 正しい式が、単位か検算のどれかに合格しない
   - `alts` の値が正しい式の極限と一致してしまう、または単位が合わない
   - 誤答候補が、どの検算でも落とせない
   - `gives` の値が数値計算と合わない
5. `src/core/bank.test.ts` の先頭にある期待値の表（`UNIT_OK` など）にも、確認済みの合否を書き足す。

レベル5（まちがい探し）は各行の正誤を機械検証できないため、追加する場合は内容を教員が確認してください。
